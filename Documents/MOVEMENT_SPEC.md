# MATE移動・経路計画仕様 V2

- 版: 0.12 / 認識合わせ用草案
- 凡例: **[合意]** 会話で明確化済み / **[仮案]** 設計提案 / **[未決]** 保留

## 1. 最上位原則

- 経路の戦術的選択はプレイヤーが行い、AIは勝手に大幅な迂回を作らない [合意]。
- 機体同士の重なり解消、隘路通過などの局所調整はゲームが自動実施 [合意]。
- 小隊ポイントは経路を作る仮座標。各機はそれ自体に拘束されない [合意]。
- **ジャンプは地形上の接続を通過する短いアクションであり、目的地への直接飛行ではない** [合意]。
- 交戦後に自律移動が原因で元経路から逸脱した場合だけ、復帰用の自動迂回を許可 [合意]。

## 2. 経路計画

プレイヤーは複数ウェイポイントを順序付きで指定する。小隊ポイントと次のウェイポイントを基準に進行経路を組み立てる。**各機は経路を参照しつつ、実位置や局所障害物に応じて動く**。ウェイポイントを勝手に書き換えない。

- [合意] 小隊ポイントの軽微なずれ（移動中の回避など）は経路へ反映する。
- [合意（2026-11-02）] 局所障害物で機体ごとの前進可否が異なる場合、通行可能な機体は進み続け、塞がれた機体は左右へ最大2機体幅まで一時退避できる。小隊内の前後順序の一時的な入れ替わりを許し、通路が空いたら安全な範囲で小隊ポイント周辺へ徐々に戻る。
- [仮案] 軽微なずれなら現在区間の接続を補正し、経路全体の再探索を頻発させない。
- [合意] 通常時に指定経路が通行できなければBLOCKEDを示し、プレイヤーが経路を直す。
- [合意] 交戦終了後はポイントを再算出し、残る経路を再評価。自律移動起因のBLOCKEDに限り、限定自動復旧。
- [未決] 将来の経路形状とどこから先を大迂回とみなすか。ウェイポイント到達半径の試作値は8.1節に記載。

## 3. 通常歩行・隊形

基本構成は3機小隊。まとまりを保って進むが、固定の3点を死守しない [合意]。隊形維持より通行を優先する状況がある。交戦中は自律行動を妨げる強い復元を禁止。著しく遊離した1機は、まとまっている2機への合流を最優先し、個別に自動復帰経路を計画する [合意]。距離閾値と合流失敗時の扱いは [未決]。

## 4. 隘路

- 狭い通路では恒常的に横へ広がらない。局所障害物を避ける一時的な横ずれは最大2機体幅まで許し、通行できる機体は進行を続ける。
- 障害物回避が不要な場面では、同方向の後続機が先頭を押したり、不必要に追い越そうとしたりしない。
- [合意（2026-11-02）] 障害物回避に必要な場合、後続機が先頭機を一時的に追い越してよい。塞がれた機体は進路が空いてから小隊ポイント周辺へ徐々に復帰する。
- 対向時は切り返し等で通過を試みる。
- 通路出口で交戦が始まっても、後続機がいつまでも不自然に足踏みしないよう状態を確認する。

### 4.1 一機ずつ通る隘路 [合意（2026-11-03）]

- 小隊ポイントから次のウェイポイントへの直線が隘路の側壁を横切る場合、経路を自動で入口へ回り込ませずBLOCKEDとする。ただし、次の操作補助に該当する場合を除く。プレイヤーは必要に応じて、入口手前や隘路内にウェイポイントを追加して通行経路を指定する。
- [合意（2026-11-03）] 隘路内から出口の先への直線が側壁に当たる場合、その直線を出口位置に延長した点が開口部の端から1.0ワールド単位以内の外側なら、出口中央を経由する経路へ補正する。許容幅はInspectorで調整でき、0なら補正しない。出口から指定ウェイポイントまでの通路が地形で塞がれている場合や、許容幅を超える場合はBLOCKEDとする。ウェイポイントは変更せず、補正後の経路を表示する。
- [合意（2026-11-03）] 隘路の外から入口側へ向かい、隘路内または反対側の出口の先を指定した場合も、同じ許容幅で直進経路を補助する。直線が入口位置で開口部の端から許容幅以内にあり、反対側まで通る場合は出口位置でも許容幅以内なら、入口中央と必要な出口中央を経由する。補正後の入口まで、隘路内、および出口からウェイポイントまでが地形で塞がれていないことを確認する。範囲外または通行不能ならBLOCKEDとする。
- 隘路の通行中に経路を変更し、すでに通路内に機体がいる場合は、通路内の機体位置から次点への直線で判定する。入口側に残る機体に小隊ポイントが引かれていても、通路内の機体の前進や引き返しを妨げない。
- 直線が隘路を横切らず、側壁にも当たらない場合は通常の経路として扱う。目的地が隘路の反対側に近いという理由だけで隘路に誘導しない。
- 各機は実際の現在位置から、機体の幅と地形を考慮して隘路の入口・通路・出口を通る歩行経路を計画する。入口へ向かうために壁を回り込む必要がある機体も、それぞれ通行可能な経路を使う。
- 小隊内では隘路の入口に近い機体から順に進入する。後続機は不要な間隔を空けずに先行機の後ろを追従する。ただし、押し合い・重なり・すり抜けは起こさない。
- 先に通過した機体は、後続機が出口を通れる空間を残して出口付近で待機する。小隊の生存機が全機通過した後、ウェイポイントへの進軍を再開する。
- ウェイポイントが隘路の内部にある場合、生存機は通路に沿って一列に整列し、全機が所定位置に着いてからその点への移動を完了する。通路端に近く全機が収まらない場合は、機体間の間隔を保ったまま列全体を通路内に収める。この場合、小隊ポイントはウェイポイントから通常の到達半径を超えて離れることがある。
- 隘路内で整列して停止した後も、新しい経路や追加済みのウェイポイントに従って前進・引き返しができる。
- 通行中に新しい経路が指定された場合は、各機の現在位置から経路と進入順を見直す。後方へ引き返す場合も、通路内の機体と入口側の待機機が衝突・閉塞しないようにする。
- 経路を置き換える指示では、同じウェイポイントを再指定した場合も現在の地形と各機の位置から通行計画を作り直す。地形によるBLOCKEDは再検査し、障害が残る場合はBLOCKEDを維持する。
- 隘路を通ることを意図した経路では、壁の外側を大きく回って隘路自体を避ける経路を選ばない。今回のテストフィールドに設けた隘路にもこの条件を適用する。ウェイポイントは書き換えない。

[未決] 隘路属性をレベル設計でどう指定するか、入口までの距離が等しい場合の順序、通過後の待機位置の具体的な決め方、一般の障害物に対して許容する自動迂回の範囲。

## 5. バーニア回避

メインアーム射撃に対しMISS（攻撃側が外す）、DODGE（防御側が実際に回避する）、HIT/BLOCKを区別する [合意]。回避時はバーニアを短時間吹かして横へ急速移動する。

- 回避候補の左右、着地点、**移動途中の占有空間**を確認する。
- 地形や味方機が塞げば回避不成立。盾防御等へ移る。
- 見た目だけでなく機体の実座標を動かす。
- 回避後に元の座標へ瞬間的に戻さない。
- **回避場所を前もって確保するために戦闘中ずっと横へ散開する挙動は禁止**。
- 回避は移動モード中にも起き得る。その位置変化は小隊ポイントと経路に軽微補正として反映 [合意]。

[未決] 回避クールダウン、回避成否とaccuracy/evasionの関係、行動範囲超過の特例。

## 6. バーニアジャンプ

### 6.1 使用目的

歩行では登れない高台など、**地形に明示されたジャンプ可能接続**を渡る。最大登坂高さの初期目安はMATE約1機分 [合意]。高さだけでは踏破可否を決めない。

### 6.2 接続データ

ジャンプ接続はテストフィールドのシーン上にノードとして配置し、起点・着地点・許可方向・着地領域を接続ごとに定義する。接続は片方向または双方向を選べる。接続先の着地領域にウェイポイントがある場合、その接続を使い、起点までは歩行してからジャンプする。高さ制約と接続許可の両方に従う。ジャンプ不許可なら同じ高さでも越えない。

プロトタイプの高低差上限は約1機体高とし、テストフィールドのInspectorから調整できるようにする。双方向接続の下降にも登坂と同じ上限を適用する。接続の着地点は3機で共有せず、各機用の位置を順番に予約する。

### 6.3 正しい移動

`現在位置 → [歩行] → ジャンプ起点 → [短いジャンプ] → 着地点 → [歩行] → ウェイポイント`

- **禁止**: 現在位置からウェイポイントへ直接大ジャンプ。
- ジャンプ前に着地点と経路の機体占有空間を検査。
- 3機が同一の着地点に同時重複しない。
- ジャンプ中は他の移動制御が位置を書き換えない。
- 着陸後は未達の経路を継続する。
- 小隊は機体ごとに順番にジャンプする。機体ごとの着地点を飛行開始前に予約し、同一点への重複着地を防ぐ。
- [合意（2026-11-02）] 着地点が足場からはみ出す場合、機体間の隊形をできるだけ維持し、着地点のまとまり全体を足場の内側へ移す。足場を確保できない場合はジャンプを開始しない。
- [合意（2026-11-02）] 飛行予定経路を他の機体が塞いでいる間はジャンプを待ち、経路が空けば順次再開する。
- [合意（2026-11-02）] 着地点スロットが同じ小隊の機体に一時的に塞がれている場合、経路全体をBLOCKEDにせず、着地点計画を固定して占有機を最大2機体幅の範囲で安全に退避させる。枠が空いた後に予約済み計画でジャンプを開始する。退避先がその時点で確保できない間は待機して再判定する。別小隊の機体や予約による占有は空くまで待ち、地形による障害はBLOCKEDとする。

### 6.4 演出

離陸時に強く噴射して跳躍し、着地前に複数回の短い制動噴射を行い、柔らかく着地する。実座標を伴う。試作初期値は所要時間0.8秒、軌道頂点は時間中点で起点と着地点を結ぶ直線から約1機体高上、着地前の制動噴射は2回とする。これらは調整可能な演出値である。

### 6.5 将来拡張

降下可能高度と登坂高度を分離する余地はあるが未確定。グレネードが遮蔽を越える可否は**移動用ジャンプ属性とは独立**に、将来の弾道/遮蔽判定で扱う [仮案]。

## 7. 交戦中の接近

敵が有効射程内にいるなら、追撃目的で接近し続けない。交戦中の各機は交戦アンカーからの行動限界を受ける。遮蔽物による射線不可は単なる射程内判定と区別する必要あり [未決]。

## 8. 移動系アーキテクチャ（実装方針）

1. **小隊指揮**: 命令、ウェイポイント、方針、交戦アンカー。
2. **行動判断**: 追撃・回避・ジャンプ等の要求。
3. **経路計画**: 歩行接続/ジャンプ接続の組み合わせ、経路復旧。
4. **移動実行**: 位置更新の唯一の責任者。衝突、安全性、移動状態を管理。

射撃・盾動作は必ずしも移動を占有しない。複数システムからの位置/速度の直接書き換えを禁止。

## 8.1 平面ウェイポイント試作 [合意（2026-10-30）]

- 地面を左クリックすると、選択小隊の未到達ウェイポイントを破棄して新しい1点を設定する。`Shift`＋左クリックは既存経路の末尾へ追加する。
- ウェイポイントは地面平面上の座標として保持し、選択小隊の経路を視覚表示する。
- 小隊ポイントは生存機の水平位置を含む最小包含円の中心とする。交戦・回避などの外部移動はまだ存在しない試作段階で、各フレームの生存機位置から再計算する。
- 各生存機は進路の次点へ向けてその場で最短角旋回し、向きの差が5度以内になってから前進する。向きが揃うまで平面位置は変えない。最後の5度以内は目標方向へ合わせてから前進し、横滑りを避ける。
- 初期向きは現状モデルの`+Z`。小隊内の全機を同じ向きにし、旋回中も各機の位置と隊形の相対配置を保つ。ウェイポイントごとに進行方向へ向き直る。通常の経路移動では後退・横移動を使わず、局所障害物回避に限り最大2機体幅の横移動と一時的な前後順の入れ替えを許す。
- 前進速度の調整可能な初期値は2.5ワールド単位/秒、旋回速度は90度/秒。小隊ポイントがウェイポイントから0.5ワールド単位以内に入ったら到達とし、次の点へ進む。
- この平面試作単体では障害物、衝突回避、地形の高低差を処理しない。ジャンプ接続プロトタイプの範囲は8.2節に定める。

## 8.2 ジャンプ接続プロトタイプ [合意（2026-11-02）]

- 接続はシーン上のノードで配置し、接続ごとに片方向または双方向を設定する。
- ウェイポイントが接続先の着地領域に含まれる場合、その接続の起点へ歩行してからジャンプし、着地後に同じウェイポイントへの移動を継続する。
- ウェイポイントが複数の明示接続を通る経路上にある場合、現在位置から目的地までの進行方向に沿う接続を順番に使う。高台への接続後は高台上を歩き、続く降下接続を渡ってから目的地へ進む。
- 接続を通過した後は同じウェイポイントに対してジャンプを再発火させず、着地位置からウェイポイントまで歩行する。
- 最大高低差は約1機体高を初期目安とし、Inspectorで調整可能にする。高低差だけでジャンプ可能とは判定せず、明示接続が必要。
- 双方向接続では下降にも同じ最大高低差を適用する。
- 3機小隊は順次ジャンプし、各機の着地点を予約して重複を防ぐ。
- テストフィールドの経路表示では、計画された各ジャンプ接続の起点を進入マーカー、着地点を着地マーカーで示し、各ペアをジャンプ軌道線で結ぶ。連続する複数接続も経路設定時に表示する。
- 飛行時間は初期値0.8秒、軌道頂点は時間中点かつ起点と着地点の線形補間位置から約1機体高上とし、下降は重力で加速する放物線にする。跳躍前と着地後に膝を曲げて重心を沈め、飛行中は膝をたたみ姿勢を変化させる。屈伸時間の初期値は各0.15秒とし、演出値は調整可能。
- ジャンプ中の実座標更新は移動実行処理だけが担当し、他の移動要求は完了後まで位置を変更しない。

## 9. 推奨実装順 [仮案]

単機歩行・停止 → 3機進軍 → 局所衝突回避 → 隘路 → 射程内停止/追撃要求 → バーニア回避 → ジャンプ接続 → 交戦後の経路再構成。各段階で回帰テストに合格してから次へ。

## 10. 優先して決める未確定事項

試作段階の決定は、将来の局所回避・隊形変更・障害物対応を確定しない。残る未決事項は隊形/機体ごとの経路追従方式、通常BLOCKEDと交戦後復旧の境界、実戦闘中の着地占有検査と機体間衝突、複層地形の代表座標、状態切替のタイミング。
