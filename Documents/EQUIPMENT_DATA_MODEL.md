# 機体・装備データモデル

## 1. 文書情報

- 対象：フロントミッションオルタナティヴ風自主制作
- 状態：暫定仕様
- 用途：MATE本体と装備品のデータ項目、および編成時の基本ルールを共有する

本書は会話で合意した方針を整理したもの。ゲーム内の数値、細かな戦闘処理、未決事項は今後の設計で更新する。

## 2. 基本方針

- 機体編成は **MATE本体、盾、メインアーム、バックユニット、拡張パーツ** の5要素で構成する。
- 現段階では防御力や属性耐性を設けず、被ダメージはHPの減少で表す。
- 実弾兵器を前提とし、電力容量・電力消費は扱わない。
- 装備重量は積載量の計算に使うが、装備が重いこと自体で移動速度を直接低下させない。機体ごとの移動速度はMATE本体側の性能として扱う。
- 装備できるかどうかは、装備品が対応するMATEによって決める。
- 数値と効果は暫定。最初から全項目を実装せず、戦闘ルールに必要なものから確定する。

## 3. 共通データ

各パーツは少なくとも次の共通情報を持つ。

| 項目 | 意味 |
|---|---|
| `id` | データ上で一意な識別子 |
| `name` | 表示名 |
| `weight` | 重量。MATEの積載量計算に使う |
| `compatible_mate_ids` | 装備可能なMATEのID一覧 |
| `description` | 任意の説明文 |
| `tags` | 任意の分類タグ。検索・効果対象指定などに使う |

対応MATEが1機だけの特注品はIDを1つ、複数機で使える装備は複数のIDを指定する。汎用化・鹵獲品の転用が進むことで対応MATEが増える、という進行を表現できる。

装備品の対応情報と、プレイヤーがいつ入手・使用可能になるかは別のデータとして管理する。互換性があることと、ゲーム進行上すでに解禁されていることは同じ意味ではない。

## 4. 5要素のデータ項目

### 4.1 MATE本体

| 項目 | 意味 |
|---|---|
| `durability_max` | 機体HPの最大値 |
| `mobility` | 機体固有の移動性能 |
| `turn_rate` | 旋回性能 |
| `load_limit` | 搭載できる重量の上限 |
| `base_weight` | 装備を除く機体重量 |

機体の合計重量は、MATE本体と装備品の重量を合算する。積載上限を超えた場合の扱い（装備不可、出撃不可など）は未決とする。装備重量から移動速度を直接引く計算は行わない。

### 4.2 盾

| 項目 | 意味 |
|---|---|
| `durability_max` | 盾HPの最大値 |
| `guard_time` | 盾を構え始めてから防御可能になるまでの時間 |

盾の基本ルール：

- 構えが完了するまでは盾の当たり判定は発生しない。
- 構え完了後、正面からの攻撃は盾HPで受ける。
- 後方からの攻撃は盾を通らず、機体HPで受ける。
- 盾HPが尽きた後の攻撃は機体HPで受ける。
- 盾が重いほどHPが高い傾向を持ち、構え時間も長くなる。
- 防御学習による構え時間短縮は、現段階のデータモデルでは扱わない。

正面とみなす角度、構え解除・再構えの処理、盾HPが尽きた瞬間の扱いは未決とする。

### 4.3 メインアーム

| 項目 | 意味 |
|---|---|
| `weapon_type` | 武器分類（例：銃、近接武器など） |
| `damage` | 1回の命中で与える基本ダメージ |
| `accuracy` | 命中判定に使う命中性能 |
| `range_min` / `range_max` | 有効射程 |
| `fire_interval` | 発射間隔 |
| `magazine_size` | 1弾倉あたりの装弾数 |
| `reserve_ammo` | 予備弾数。必要な武器のみ設定 |
| `reload_time` | リロード時間。必要な武器のみ設定 |
| `recoil` | 反動など、採用する場合の武器特性 |

電力消費は持たせない。弾薬の単位（弾倉数か総弾数か）、命中率・射程・反動の計算方式は未決とする。

### 4.4 バックユニット

バックユニットは、推進器や追加武装など異なる用途を持つ装備枠。共通項目に加え、種類に応じた性能を持つ。

| 項目 | 意味 |
|---|---|
| `unit_type` | ユニット分類（例：高機動、ミサイル、追加燃料） |
| `effect` | 分類に応じた性能・戦闘効果 |
| `ammo_capacity` | 弾薬を持つ場合の最大弾数 |
| `reload_time` | 再装填がある場合の時間 |

具体的なユニット種別と効果は、戦闘ルールに応じて定義する。

### 4.5 拡張パーツ

拡張パーツは、火器管制、追加弾倉、CIWS、ナイトビジョンなど、機体の運用特性を追加・変更する装備枠。パーツごとに異なる効果を持てるため、個別の全項目を共通データへ並べず、効果のリストとして表現する。

概念例：

```text
ExpansionPart
  common fields
  effects: [Effect, ...]

Effect
  type: 効果種別
  parameters: 効果種別ごとの設定値
```

効果の候補例：

| 効果種別 | 主なパラメータ例 |
|---|---|
| 高機動補助 | 移動性能・加速などの補正 |
| 火器管制 | 命中補正、照準時間など |
| 追加弾倉 | 対象武器または武器タグ、追加弾数 |
| CIWS | 対象、迎撃性能 |
| ナイトビジョン | 暗所での索敵・視認補助 |

効果リスト方式なら、1つのパーツに複数の効果を持たせられる。どの効果種別を正式採用するか、効果値をどう適用するかは別途決める。

## 5. 編成データ

パーツの定義データと、実際に組んだ機体の状態は分けて管理する。

```text
MateLoadout
  mate_id
  shield_id: optional
  main_arm_id: optional
  back_unit_id: optional
  expansion_id: optional
```

編成データは装備品IDを参照する。現在HP、現在弾数、盾HPなどの戦闘中に変化する値は、編成定義に混ぜず、戦闘中の機体状態として保持する。

テストフィールドでは、機体状態を編成とは別の `MateUnitState` Resource として機体ごとに作成する。静的な初期表示では現在HP・盾HP・バックユニット弾数を、対応する各定義の最大値で初期化する。HUDと3Dプレビューは同じ機体状態を参照し、戦闘シミュレーション導入後はこの状態を更新元とする。

テストフィールドの暫定編成は各小隊3機で、同じ小隊内の機体・装備・塗装を揃える。第一小隊のみバックユニットとして縦長キャノン砲を装備し、他小隊はバックユニットなしとする。キャノン砲は静的な待機姿勢で表示し、構え・照準アニメーションと射撃処理は含めない。

## 6. 未決事項

- 積載上限を超えた編成を許すか、どのタイミングで制限するか。
- 装備枠ごとに未装備を許すか。拡張パーツ枠を複数にする可能性。
- 盾の正面防御角度と、構え・解除・破損後の挙動。
- 武器の命中・射程・弾薬・リロードの具体的な計算ルール。
- バックユニットの分類と、それぞれの効果。
- 拡張パーツの正式な効果一覧と、複数効果の適用順。
- MATE互換性の解禁条件、鹵獲品の運用開始条件。
- データはGodotのResource（`.tres`）で持つ（決定済み）。
